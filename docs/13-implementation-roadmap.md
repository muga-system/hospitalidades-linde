# 13 — Roadmap de implementación

## Fase 0 — Referencia + base

- Leer documentación.
- Si hay acceso web, inspeccionar home y páginas de referencia.
- Identificar 8–12 decisiones visuales no negociables.
- Inicializar Astro + TS.
- Configurar tokens, fuentes, reset y layout.

**Salida:** shell inicial cuyo header, escala y superficies ya apunten visualmente al referente.

## Fase 1 — Home como prueba de dirección

Antes de construir todo el sitio:

- header/menu;
- hero;
- primer bloque posterior;
- una pieza de catálogo;
- una pieza de proyecto;
- footer parcial.

Comparar desktop/mobile contra HUTS.

**Gate:** si se siente como un sitio genérico de arquitectura, corregir antes de avanzar.

## Fase 2 — Datos y componentes reales

- tipos;
- site config;
- modelos;
- soluciones;
- proyectos;
- componentes surgidos de patrones reales.

## Fase 3 — Home completa

Implementar todas las secciones y revisar ritmo de punta a punta.

## Fase 4 — Catálogo y soluciones

- `/modelos/`;
- `/modelos/[slug]/`;
- `/soluciones/`;
- `/soluciones/[slug]/`.

Comparar páginas equivalentes del referente.

## Fase 5 — Portfolio

- mapa primero;
- grilla;
- filtros;
- detalle de proyecto.

Portfolio es una segunda prueba de fidelidad crítica.

## Fase 6 — Proceso, servicios, estudio y guías

Mantener el mismo sistema de escala/ritmo; no degradar a templates secundarios.

## Fase 7 — Wizard

Formulario multipaso, validación y éxito demo.

## Fase 8 — Motion

Recrear tempo e interacción equivalentes usando implementación propia.

## Fase 9 — Visual QA

Capturar o inspeccionar al menos:

- home desktop;
- home mobile;
- modelos index;
- modelo detalle;
- portfolio mapa;
- portfolio grilla;
- proyecto detalle;
- menú desktop/mobile;
- wizard.

Comparar composición, escala, ritmo y densidad con el referente.

## Fase 10 — QA técnico

- responsive;
- teclado;
- reduced motion;
- Lighthouse;
- enlaces;
- mapa;
- wizard;
- 404;
- build.

## Fase 11 — Preparación comercial

- reemplazar placeholders;
- revisar copy;
- capturas;
- deploy.
